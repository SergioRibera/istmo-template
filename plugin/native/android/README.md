# Android reference backend

`{{crate_name | pascal_case}}FactoryImpl` builds a
`{{crate_name | pascal_case}}BackendImpl` per client instance. Apps that
depend on this crate get both files compiled into their Android module
by the `io.github.sergioribera.istmo` Gradle plugin, and the generated
`IstmoPluginRegistry` registers the factory (named by `android_backend`
in `istmo.toml`) before the Rust entry point runs — no manual wiring.

The `{{crate_name | pascal_case}}Backend` / `{{crate_name | pascal_case}}Factory`
interfaces and the `{{crate_name | pascal_case}}Config` / `{{crate_name | pascal_case}}Error`
types are generated by the consuming app's `build.rs` from the Rust
trait, into this directory's package (`android_package` in
`istmo.toml`), so these sources use them without imports. Method names keep the Rust spelling
(`get_value`), field names are camelCase (`exampleSetting`).

Apps that build this backend themselves set `auto_register = false` for
this plugin and register it after `IstmoHost.onCreate(this)`:

```kotlin
IstmoRuntime.registerHandler(
    {{crate_name | pascal_case}}Dispatcher.PLUGIN_ID,
    {{crate_name | pascal_case}}Dispatcher(
        {{crate_name | pascal_case}}FactoryImpl(applicationContext),
        {{crate_name | pascal_case}}CodecsImpl(),
    ),
)
```
